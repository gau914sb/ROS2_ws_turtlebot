PHASE 1: QoS Configuration
---------------------------
Issue: ROS2 subscribers not receiving PX4 status updates
Fix Applied: Changed QoS durability from TRANSIENT_LOCAL to VOLATILE
Result: ✅ Status updates now received correctly
File: single_drone_takeoff_land.py (QoS profile around line 88)

PHASE 2: Namespace Configuration  
--------------------------------
Issue: Confusion about instance numbering (0 vs 1) and namespace format
Testing Results:
- Official PX4 uses instance 1 for first drone → /px4_1/fmu namespace
- Instance 0 would use /fmu namespace (not tested)
- Modified PX4-Autopilot-ADS used /px4_0, /px4_1, /px4_2 format
Result: ✅ Namespaces correctly configured for instance 1
File: single_drone_takeoff_land.py (line ~65)

PHASE 3: PX4 "Proof-of-Life" Heartbeat
---------------------------------------
Issue: PX4 requires continuous OffboardControlMode stream before accepting mode switch
Requirements discovered:
- Minimum 2Hz OffboardControlMode publishing
- Must stream for at least 1 second before mode switch attempt
- Must continue publishing EVERY control loop cycle

Implementations tried:
1. Initial: 50 cycles (1 second) streaming
2. Final: 100 cycles (2 seconds) streaming at 50Hz

Result: ✅ OffboardControlMode heartbeat working at 50Hz
Verification: `ros2 topic hz /px4_1/fmu/in/offboard_control_mode` shows 49.99 Hz
File: single_drone_takeoff_land.py (State.INIT, line ~217)

PHASE 4: PX4 Parameters
-----------------------

Parameter: COM_OF_LOSS_T

- Status: ✅ Acceptable default

Parameter: COM_OBL_RC_ACT
- Value: 0 (no action on offboard RC loss)
- Status: ✅ Correct for autonomous operation

================================================================================
FINAL DIAGNOSIS
================================================================================

ROOT CAUSE:
PX4's XRCE-DDS client for multi-vehicle instance 1 does NOT route VehicleCommand
messages to the commander module, despite:
- Topics existing correctly
- Messages being published correctly
- PX4 receiving the data (confirmed by Payload rx)
- Subscriptions being established

This is likely a PX4 configuration issue or limitation with multi-vehicle
XRCE-DDS setups where instance IDs > 0 don't process external commands.

WHAT WORKS:
✅ OffboardControlMode heartbeat (50Hz)
✅ TrajectorySetpoint control
✅ VehicleStatus monitoring
✅ State machine logic
✅ Autonomous trajectory control
✅ Altitude control and setpoint tracking
✅ Complete mission execution (with manual trigger)

WHAT DOESN'T WORK:
❌ VehicleCommand via ROS2 (silently ignored by PX4)
❌ Autonomous arm/disarm via ROS2
❌ Autonomous mode switching via ROS2

================================================================================

Procedure:

4. Wait 3 seconds for OffboardControlMode heartbeat
5. Manual trigger in PX4 console:
   - `commander mode offboard`
   - `commander arm`
6. Script takes over and completes full autonomous mission

CONCLUSION

logic, trajectory following, and autonomous behavior works perfectly when
manually triggered.

routed to the commander module for multi-vehicle instances (instance 1+).
